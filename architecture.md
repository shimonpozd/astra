# Astra User Management & LLM Keys — текущая архитектура

## 1. Текущее состояние функций
- **Аутентификация**:  
  - Бэкенд (`brain_service`) даёт JWT через `/api/auth/login`; refresh отсутствует, токен одноразовый на 60 минут.  
  - Админ доступ проверяется в `require_admin_user` (роль `admin` в таблице `users`).  
  - CLI-скрипт `brain_service/scripts/create_user.py` позволяет создавать/обновлять пользователя через консоль (bcrypt_sha256, поддержка длинных паролей).
- **Сессии**:  
  - `SessionService` хранит данные чатов/учебных сессий в Redis (ключи `session:{user}:{id}` и `study:sess:{id}:top`).  
  - Сайдбар на фронте (`useChat`) запрашивает `/api/sessions` и группирует чаты/daily/study.
- **LLM вызовы**:  
  - Конфигурация берётся из `config/*` → `core.llm_config`. Поддерживаются провайдеры `ollama` и `openrouter`/`openai`.  
  - Сейчас ключи глобальные: `OPENROUTER_API_KEY` / `OPENAI_API_KEY` из конфигов, общие на всех пользователей.  
  - `LLMService` инжектирует STM-контекст из Redis и стримит ответы (пока заглушка, но структура заложена).  
  - Ограничения на уровне пользователей отсутствуют; usage не считается.
- **Админ-панель (frontend)**:  
  - Вкладки: `General Settings`, `Personalities`, `Prompts`.  
  - Пользователи и ключи не отображаются; пока админ может управлять только конфигурацией LLM и наборами персон.
- **Диагностика**:  
  - После фикса `httpx` (<0.28) восстановлена работа OpenRouter, логин и учебные сессии вновь функционируют.  
  - Режим `RequireAuth admin` защищает админский роутинг, `Study`/`Daily` сессии снова отображаются с названиями (ref по тексту).

## 2. Архитектура решения (на которую опираемся)

### Бэкенд
- **FastAPI**: модули `brain_service/api/*` (auth, chat, study, admin).  
- **ORM**: SQLAlchemy 2.0 (`brain_service/models/db.py`). Таблица `users` — источник ролей и статусов.  
- **Сервисы**: слой `brain_service/services/*`:
  - `user_service` — работа с пользователями;
  - `session_service` — метаданные чат/стади;
  - `study_service` — логика учебного режима;
  - `llm_service` — подготовка запросов к модели (интеграция с STM, STM обновление).  
- **Конфигурация**: `config/defaults.toml` + `overrides` через `core/settings`.  
- **Хранилища**: Postgres (`DATABASE_URL`) и Redis (`REDIS_URL`). Redis используется как state-store; API ключи пока нигде не хранятся.

### Фронтенд
- **Vite + React/TypeScript** (`astra-web-client`).  
- **AuthContext** / `RequireAuth` — защищает роуты; `TopBar` отображает пользователя и кнопку Admin.  
- **AdminLayout** — навигация по админским вкладкам. Пока нет UI для пользователей.  
- **Hooks**: `useChat`, `useStudyMode`, `useAuth`. Для будущего управления пользователями потребуется новый hook (например, `useAdminUsers`).  
- **Сервисы**: `src/services/api.ts`, `services/auth.ts`; авторизованные запросы через `authorizedFetch` (добавляет Bearer токен, реагирует на 401).  
- **UI**: составные компоненты на основе shadcn UI (Select, Button, Table). Настроенный `ThemeProvider` / `LayoutContext`.

## 3. Гарантии и зависимости
- **Безопасность**: пароли хранятся как `bcrypt_sha256`; JWT выдаётся локально; админ-панель защищена ролью.  
- **Распределение ключей**: сейчас один глобальный OpenRouter ключ; строгие лимиты отсутствуют. Это мотивирует будущую работу по индивидуальным ключам.  
- **Testing**: в репозитории есть `brain_service/tests/unit`, но новые сценарии (пользователи/ключи) ещё не покрыты.  
- **Документация/скрипты**: `deploy/brain_service/README.md` описывает деплой; новый план (`plan.md`) фиксирует шаги по пользовательскому управлению.
